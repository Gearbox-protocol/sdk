# Adapter safe-price return inventory

`classifyAdapterSafePrices` answers which boolean an adapter returns to the credit facade **if this particular call succeeds**. It does not validate execution, estimate swap outputs, or decide whether a future withdrawal will mature. The facade accumulates true flags; a false adapter return never clears a flag set earlier in the multicall.

The executable method inventory is the `rules` table in `src/onchain/market/adapters/safe-prices.ts`. Only the listed adapter type, exact version, and decoded operation are recognized. The actual calldata selector selects the ABI overload before the method rule is applied. Getters and administration methods are excluded even when their ABI returns a boolean. Unsupported operations/versions are different from a reviewed operation whose balance-dependent return is unresolved.

## Reviewed source snapshots

- [Integrations 39e70f05](https://github.com/Gearbox-protocol/integrations-v3/tree/39e70f05e09ef4224febb3a8c9890afe48adbec9/contracts/adapters) supplies the older adapter layout and Infinifi/Upshift.
- [Integrations 096d9b18](https://github.com/Gearbox-protocol/integrations-v3/tree/096d9b18f943de1ee73b28daa530f27f31f57577/contracts/integrations) is the integration dependency checked out by periphery; it supplies Midas Gateway and the newer Midas/Securitize versions.
- [Kelp before removal, 48efe2f7](https://github.com/Gearbox-protocol/integrations-v3/tree/48efe2f73c00bcb34976ae29768c32a8321c6e8b/contracts/adapters/kelp) supplies both Kelp v310 implementations.
- [ERC4626 v310, d9934d77](https://github.com/Gearbox-protocol/integrations-v3/blob/d9934d77657878f60ba81ecd73546a6a4aaf833a/contracts/adapters/erc4626/ERC4626Adapter.sol) and [v311, 574b1fba](https://github.com/Gearbox-protocol/integrations-v3/blob/574b1fba045183714f2df205a62dfba9d803ebcb/contracts/adapters/erc4626/ERC4626Adapter.sol) supply historical plain-vault return behavior.

In the following inventory, **conditional** means false when the inspected input balance is at most the leftover, and true otherwise, unless an exception is explicitly stated. All claims concern successful adapter returns, including successful no-op branches. A return classification alone does not prove an otherwise reverting zero-amount external operation succeeds.

## Explicit limits

Mellow ERC4626 v311 is not classified: [574b1fba](https://github.com/Gearbox-protocol/integrations-v3/commit/574b1fba045183714f2df205a62dfba9d803ebcb) changed withdrawal return flags without bumping its version, including making redeemDiff true even when the inherited call no-ops. Type/version alone cannot distinguish both implementations. A runtime-code identity or separately verified deployment inventory is needed before enabling it. Unlisted historical versions similarly remain unsupported; no numeric version interval is assumed safe.

The context supplies exact pre-call balances or guaranteed min/max bounds. A quoted or expected amount must not populate these bounds. A diff resolves true only when the entire range lies on the executing side, false only when the entire range lies on the no-op side. Overlapping/invalid ranges remain state-dependent. No quote or fabricated balance replaces missing metadata.

Kelp's withdrawal SDK object lacks rsETH, native Uniswap V4 pools lack WETH metadata, and two Pendle methods need PT lookup through `market.readTokens()`/`YT.PT()`. These reviewed methods can remain state-dependent even when balances are available. Missing serialized adapter metadata is also unresolved. Getter errors are not interpreted as zero balances. Future delayed-withdrawal schedules are outside this classifier; actually callable request and claim calldata are classified now using their adapter return behavior.
